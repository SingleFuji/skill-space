# 智能旅行规划师 · 产品设计文档

> 从"查路线"到"管全程"的旅行规划产品升级方案。

---

## 一、产品概述

### 1.1 产品定位

一款**面向自由行用户的智能旅行规划助手**，覆盖旅行决策的全链路：从需求理解、方案设计、预算管理、住宿餐饮推荐，到出行保障和备选预案。

### 1.2 核心价值

| 对比项 | 传统做攻略 | 本产品 |
|-------|-----------|--------|
| 信息收集 | 刷十几篇攻略拼信息 | 一次输入即可 |
| 方案比选 | 手动比对交通/住宿 | 自动多方案比选 |
| 预算控制 | 靠感觉估算 | 分项预算 + 优化建议 |
| 行程排布 | 手动做 Excel/备忘录 | 按天/时段自动规划 |
| 应急处理 | 出发后才发现问题 | 提前预判 + 备选方案 |

### 1.3 用户场景

| 场景 | 典型用户 |
|------|---------|
| 周末自驾游 | 城市年轻人，2-4 人 |
| 长假自由行 | 上班族，5-10 天 |
| 家庭出游 | 带老人/孩子 |
| 出差 + 游玩 | 商务人士 |
| 毕业旅行 | 学生群体，预算敏感 |
| 出境自由行 | 年轻白领 |

## 二、产品架构

### 2.1 功能架构

```
旅行规划产品
├── 1. 需求解析层
│   ├── 意图识别（目的地/天数/人数/预算/偏好）
│   ├── 信息补全（提问策略：一次只问关键缺失项）
│   └── 理解确认（回显确认机制，减少理解偏差）
│
├── 2. 方案设计层
│   ├── 交通方案（多方式比选 ≥ 2 种）
│   │   ├── 飞机（直飞/中转比价）
│   │   ├── 高铁/火车（车次/时长/票价）
│   │   ├── 自驾（距离/耗时/费用估算）
│   │   └── 大巴/轮船（特殊场景）
│   │
│   ├── 日行程排程
│   │   ├── 按天/时段分解
│   │   ├── 景点间距离优化
│   │   ├── 弹性缓冲时间
│   │   └── 强度适配（老人/儿童/特种兵）
│   │
│   ├── 住宿推荐
│   │   ├── 分档次（经济/舒适/精品/奢华）
│   │   ├── 分区域（区位推荐 + 距离标注）
│   │   └── 具体推荐（名称/价格/评分/优缺点）
│   │
│   ├── 美食指南
│   │   ├── 必吃特色
│   │   ├── 正餐推荐（分餐次/区域）
│   │   ├── 小众/本地人推荐
│   │   └── 避雷提醒
│   │
│   └── 游玩体验
│       ├── 核心景点（门票/时段/游览时长）
│       ├── 小众/深度体验
│       ├── 购物推荐
│       └── 文化/节庆活动
│
├── 3. 预算管理层
│   ├── 分项预算（交通/住宿/餐饮/门票/当地交通/其他）
│   ├── 预算 vs 实际对比
│   ├── 省钱建议
│   └── 升级/删减项
│
├── 4. 出行保障层
│   ├── 天气预警（出行期间逐日天气）
│   ├── 证件检查清单
│   ├── 打包清单（按季节/场景定制）
│   ├── 保险建议
│   ├── 备选方案（天气/排队/交通延误）
│   └── 紧急信息（医院/使馆/报警电话）
│
└── 5. 增值服务层（V2.0+）
    ├── 行程单导出（PDF/图片/日历导入）
    ├── 多人协作编辑
    ├── 实时信息刷新（票价/天气/人流）
    ├── 行程分享（微信/小红书格式）
    └── 智能提醒（出发前/天气变化/特价推送）
```

### 2.2 信息流

```
用户输入 ──→ 需求解析 ──→ 信息补全（如需） ──→ 理解确认
                                                    │
                                                    ↓
                            ┌─── WebSearch 搜索 ────┐
                            │  交通 / 景点 / 住宿   │

                            └─────────┬────────────┘

                            输出完整旅行方案
                                      │
                                      ↓
                            用户反馈调整 (可选)
```

## 三、核心算法逻辑

### 3.1 行程排程算法

```
输入：景点列表 + 时间预算 + 用户偏好
输出：优化后的日行程

约束条件：
1. 相邻景点地理距离最小化（减少路上时间）
2. 热门景点安排在非高峰时段（早去或晚去）
3. 每半天至少留 1h 弹性缓冲
4. 餐饮时间在合理时段（11:30-13:00 午 / 17:30-19:00 晚）
5. 每天总景区游览时间 ≤ 6h（普通） / ≤ 4h（老人/儿童）
```

### 3.2 预算估算模型

```
总预算 = 交通 + 住宿 + 餐饮 + 门票 + 当地交通 + 其他

各项估算：
- 交通：搜索实时或参考价 × 人数
- 住宿：分档均价 × 晚数
- 餐饮：人均日消费 × 天数 × 人数 × 系数（普通1.0/舒适1.3/豪华1.8）
- 门票：核心景点票价 × 景点数 × 系数（全部去1.0/精选0.7）
- 当地交通：日均 ¥50-100/人（打车）或 ¥30/天（公共交通）
- 其他：总预算 × 10%（预留弹性）
```

### 3.3 推荐排序逻辑

住宿/美食/景点推荐遵循以下优先级：
1. **相关性**：与用户目的地的匹配度
2. **评分**：参考主流平台评分（≥ 4.0/5.0）
3. **性价比**：价格与体验的综合评价
4. **独特性**：地方特色优先于全国连锁
5. **时效性**：最新评价优先

## 四、用户交互设计

### 4.1 交互原则

| 原则 | 说明 |
|------|------|
| 最小输入 | 只说目的地+天数就能出方案，其他信息可后补 |
| 理解确认 | 正式输出前回显理解，避免方向性错误 |
| 渐进式输出 | 先给概览，再展开细节，不一次性全输出 |
| 可调性 | 每个方案都标注"可以调"，降低修改门槛 |
| 一次性给出成品 | 不废话，直接给可执行的行程单 |

### 4.2 典型对话流程

```
用户：我想去大理玩3天
┌─────────────────────────────────────────────┐
│  AI：📌 按以下理解规划：                      │
│      大理 3天2晚 | 从昆明出发 | 一个人       │
│      需要补充：预算和偏好？                   │
│      1️⃣ 预算 2000/4000/6000+ ?              │
│      2️⃣ 偏好 休闲/紧凑/美食/拍照/全都要？    │
│      (直接说数字或关键词即可)                 │
└─────────────────────────────────────────────┘
用户：预算4000，休闲+美食
┌─────────────────────────────────────────────┐
│  AI：[输出完整方案，含概览/交通/行程/住宿/   │
│      美食/预算/贴士]                         │
│                                              │
│      需要调整语气/天数/景点/预算吗？          │
└─────────────────────────────────────────────┘
```

### 4.3 调整交互

用户提出调整时，支持精确修改：

| 用户说 | AI 响应 |
|-------|---------|
| "第二天太赶了" | 减少第二天景点，移部分到第三天或删除 |
| "换个便宜点的住宿" | 替换为下一档住宿推荐，更新预算 |
| "加一个苍山" | 插入苍山到合适时段，调整后续行程 |
| "预算降到3000" | 重新估算，给出减配方案 |

## 五、版本迭代规划

### V1.0 — 功能 MVP（当前版本）

- 国内自由行规划
- 自驾游路线规划（保留原 skill 的百度地图导航链接输出）
- 交通/行程/住宿/美食/预算/贴士 全链路
- 天气查询 + 打包清单 + 备选方案
- 支持出差+游玩混合场景
- 支持家庭（老人/儿童）和多人出行

### V2.0 — 体验升级（下一阶段）

- 出境游规划（签证/时差/插头/紧急电话/小费文化）
- 行程单导出（Markdown 直接可复制为周报/笔记）
- 多人场景深度优化（团建/蜜月/亲子分类模式）
- 实时信息刷新（临近出发时重新搜索票价和天气）
- 行程分享格式优化（小红书/微信适配）

### V3.0 — 智能增强（远期）

- 用户画像记忆（记住常住地/偏好/预算习惯）
- 智能推荐优化（基于历史行程的学习）
- 动态行程调整（出发后根据实际情况调整后续计划）
- 社区内容整合（推荐热门的本地人路线）

## 六、竞争对标

| 维度 | 传统攻略平台(马蜂窝/穷游) | AI 助手(ChatGPT) | 本产品 |
|------|------------------------|-----------------|--------|
| 信息时效性 | 依赖用户上传，可能过时 | 可搜索实时信息 | 可搜索实时信息 |
| 个性化 | 通用攻略，千人一面 | 可定制 | 结构化定制 |
| 方案完整度 | 分散信息，需自整合 | 回答偏通用 | 全链路一站式 |
| 预算管理 | 无 | 估算较粗 | 分项预算+优化 |
| 出行保障 | 无 | 有基本提示 | 天气/证件/打包/备选 |
| 交互体验 | 搜索→浏览→自整理 | 对话式 | 确认机制+成品输出 |

## 七、质量指标

### 7.1 核心 KPI

| 指标 | 目标 |
|------|------|
| 方案完整性 | 每次输出覆盖 ≥ 6 个模块 |
| 交通方案比选 | ≥ 2 种方案 |
| 日行程排程合理性 | 景点间路径优化、弹性缓冲 ≥ 1h/半天 |
| 预算估算偏差 | 参考价与主流平台差异 ≤ 15% |
| 用户一次满意率 | 首次输出即满足需求的比例 ≥ 70% |

### 7.2 反例 / 应避免

| ❌ 不要这样做 | ✅ 应该这样做 |
|-------------|------------|
| 只给文字不给结构 | 表格/清单/时间轴结构化输出 |
| 只说"建议去XX"不说理由 | 每个推荐附简要理由 |
| 只推荐热门景点 | 覆盖特色体验 + 小众选项 |
| 输出后不管了 | 主动问"需要调整吗" + 给精确修改方向 |
| 不标注价格区间 | 所有推荐含参考价格 |
| 不做备选方案 | 至少准备天气和排队的备选 |
