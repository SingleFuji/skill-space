## 1. 产品背景

### 1.1 业务背景

短期意外健康险业务快速增长，各险企经营数据分散在核心系统、财务系统、理赔系统等多个数据源中。管理层和业务负责人缺乏统一视图来实时掌握经营状况。

目前存在的问题：
- **数据孤岛**：保费在核心系统，理赔在理赔系统，费用在财务系统，综合查询需多系统切换
- **对比维度缺失**：看当前值但看不到同比/环比，看达成率但看不到市场份额，决策缺乏参照系
- **响应滞后**：异常指标靠人工发现，从异常出现到被关注平均滞后 2-3 周

### 1.2 对标基准

参照头部保险公司（人保、平安、太保、国寿财、中华联合）的经营看板指标体系，对标行业通用的四维对比框架：**当前值 vs 历史趋势 vs 预算目标 vs 市场竞品**。

## 2. 产品目标

### 2.1 核心目标

| 目标 | 衡量指标 | 目标值 |
|------|---------|-------|
| 统一数据视图 | 覆盖核心经营指标数 | ≥ 50 个 |
| 缩短数据获取时间 | 从提出需求到获取数据的时间 | 从 2 天缩短到 < 5 分钟 |
| 异常发现时效 | 从异常发生到预警推送 | ≤ T+1 日 |
| 用户覆盖率 | 目标用户日常使用率 | ≥ 80% |

### 2.2 关键能力

1. **四维对比**：每个指标都能看到当前值、历史趋势、预算达成、市场对标
2. **下钻能力**：支持从公司层 → 渠道/产品 → 地区 → 团队/个人的逐级下钻
3. **预警机制**：关键指标超出阈值时自动标红/推送
4. **自助分析**：用户可选择不同的对比维度和时间范围

## 3. 目标用户

### 3.1 用户角色矩阵

| 角色 | 核心关注 | 使用频率 | 访问深度 |
|------|---------|---------|---------|
| **CEO / 高管** | 总览页核心指标、承保利润、市场排名 | 每日晨会 | 只看总览 |
| **承保/渠道负责人** | 保费趋势、渠道分析、产品结构、达成进度 | 每日 | 总览 + 承保页 |
| **理赔负责人** | 赔付率、结案率、异常案件、时效 | 每日 | 总览 + 理赔页 |
| **财务/精算** | 综合成本率、费用明细、利润预测 | 每周 | 损益页为主 |
| **战略/企划** | 市场对标、竞品追踪、排名变化 | 每月 | 市场对标页为主 |

### 3.2 用户权限

| 角色 | 可查看页面 | 可下钻层级 | 可导出 |
|------|----------|-----------|-------|
| 高管 | 全部页面 | 公司级 + 渠道级 | 是 |
| 部门负责人 | 对应页面 + 总览 | 公司级 → 地区级 | 是 |
| 分公司 | 总览 + 本分公司数据 | 本公司级 → 团队级 | 本分公司 |
| 只读用户 | 总览页（脱敏版） | 公司级 | 否 |

## 4. 整体架构

### 4.1 产品结构

```
┌──────────────────────────────────────────────────────┐
│                    顶部导航栏                          │
│   📊总览  📋承保分析  🩺理赔分析  💰损益分析  🏢市场对标 │
├──────────────────────────────────────────────────────┤
│                                                      │
│               Tab 内容区域（五选一）                    │
│  ┌──── KPI 卡片区（总览页专属，其他页可能有简版）───┐  │
│  │                                                    │  │
│  ├──── 图表区 ──────────────────────────────────────┤  │
│  │  折线图 / 柱状图 / 瀑布图 / 条形图                │  │
│  ├──── 数据表格区 ──────────────────────────────────┤  │
│  │  支持排序、筛选、导出                             │  │
│  └──────────────────────────────────────────────────┘  │
│                                                      │
└──────────────────────────────────────────────────────┘
```

### 4.2 页面导航

- **Tab 切换**：点击切换，URL 带 hash（支持浏览器前进/后退）
- **页面联动**：从总览页指标卡片可单击跳转到对应详情页
- **下钻路径**：总公司 → 分公司 → 中支 → 团队 → 个人（各级权限控制）

## 6. 数据需求

### 6.1 数据源

| 数据域 | 来源系统 | 数据内容 | 更新频率 |
|-------|---------|---------|---------|
| 承保 | 核心业务系统 | 保单信息、保费、渠道、产品、续期 | 实时 |
| 理赔 | 理赔系统 | 报案、立案、结案、赔付金额 | 实时 |
| 财务 | 财务系统 | 费用、佣金、准备金、税金 | T+1 |
| 精算 | 精算系统 | 已赚保费、IBNR 准备金 | 月度 |
| 市场 | 监管披露/行业数据 | 市场规模、竞品数据、份额 | 月度/季度 |
| 目标 | 预算系统 | 年度/月度预算目标 | 年度 |

### 6.2 数据口径

**关键指标计算公式**（全部对齐行业通用口径）：

| 指标 | 计算公式 | 备注 |
|------|---------|------|
| 规模保费 | 全部保单保费合计（含分出） | — |
| 原保费收入 | 规模保费 - 分出保费 | — |
| 已赚保费 | 原保费收入 - 未到期责任准备金提转差 | 精算口径 |
| 综合成本率 | (已发生赔款 + 费用) / 已赚保费 × 100% | 核心监控指标 |
| 赔付率 | 已发生赔款 / 已赚保费 × 100% | — |
| 费用率 | (手续费佣金 + 管理费 + 税金) / 已赚保费 × 100% | — |
| 结案率 | 已决件数 / (已决 + 未决)件数 × 100% | — |
| 市场份额 | 本公司保费 / 市场总保费 × 100% | 监管披露口径 |
| 续期率(13M) | 13 个月前保单中按时缴费的比例 | 通用行业口径 |
| 案均赔款 | 赔付金额 / 已决件数 | — |

### 6.3 数据更新优先级

| 更新时效 | 适用数据 | 实现难度 |
|---------|---------|---------|
| 实时（T+0） | 报案数、立案数 | ★★ |
| 日更（T+1） | 保费收入、承保件数、理赔金额、结案率 | ★★ |
| 周更 | 费用明细（初步数） | ★★★ |
| 月更 | 已赚保费、综合成本率、赔付率、市场份额 | ★★★ |
| 季更 | 竞品完整数据、行业深度分析 | ★★★★ |

## 7. 非功能性需求

### 7.1 性能需求

| 需求 | 指标要求 |
|------|---------|
| 页面加载时间 | ≤ 3 秒（首屏） |
| 数据查询时间 | ≤ 5 秒（复杂查询） |
| 图表渲染时间 | ≤ 2 秒 |
| 并发用户数 | ≥ 200 人同时在线 |
| 数据导出时间 | ≤ 10 秒（万级数据量） |
| 日终数据刷新 | ≤ 30 分钟完成全量更新 |

### 7.2 安全需求

| 需求编号 | 需求描述 | 优先级 |
|---------|---------|-------|
| SEC-01 | 用户登录认证，对接公司统一 SSO | P0 |
| SEC-02 | 基于角色的权限控制（RBAC），限定用户可查看的数据范围和下钻深度 | P0 |
| SEC-03 | 敏感数据脱敏（客户个人信息不可出现在看板上） | P0 |
| SEC-04 | 操作审计日志，记录所有数据查询和导出行为 | P1 |
| SEC-05 | 数据导出加水印（含用户名、时间、查询条件） | P2 |

### 7.3 可用性需求

| 需求编号 | 需求描述 | 优先级 |
|---------|---------|-------|
| UX-01 | 系统可用性 ≥ 99.5%（核心交易时段 8:00-20:00） | P0 |
| UX-02 | 数据不完全时显示加载状态骨架屏，而非空白 | P1 |
| UX-03 | 数据异常时显示错误提示，而非直接白屏 | P1 |
| UX-04 | 支持主流浏览器（Chrome / Edge / 微信内置浏览器最新版） | P1 |

### 7.4 数据质量

| 需求编号 | 需求描述 | 优先级 |
|---------|---------|-------|

| DQ-02 | 数据源接口异常时触发数据质量告警 | P1 |
| DQ-03 | 市场对标数据标注数据来源和置信度（监管披露/行业交流/估算） | P1 |

| 需求 | 要求 |
