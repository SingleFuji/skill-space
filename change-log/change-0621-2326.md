### 2. 核心 SQLite 数据库工具实现 (`skills/sqlite-mcp-server/src/index.ts`)
这是新技能的核心文件，实现了 MCP 服务器并注册了四个关键的 SQLite 数据库操作工具。

*   **数据库连接管理**:
    *   `getDb()`: 用于获取可读写的 SQLite 数据库连接。它要求 `SQLITE_DB_PATH` 环境变量必须设置，并会验证数据库文件及其所在目录是否存在。为了性能，它将数据库的日志模式设置为 `WAL` (Write-Ahead Logging)。
    *   `getReadonlyDb()`: 用于获取只读的 SQLite 数据库连接，同样依赖 `SQLITE_DB_PATH` 环境变量。
*   **结果截断**:
    *   `truncateResult(text: string, resultCount: number)`: 此函数用于限制返回给客户端的文本结果长度，最大字符限制为 `CHARACTER_LIMIT = 50000`。如果结果超出此限制，将添加截断消息，提示用户使用 `LIMIT/OFFSET` 或 `WHERE` 过滤器。
*   **`sqlite_query` 工具**:
    *   **功能**: 允许执行 `SELECT`, `PRAGMA`, `WITH` 等只读 SQL 查询。
    *   **输入**: 接收 `sql` (SQL 语句字符串) 和可选的 `params` (用于参数化查询的数组)。
    *   **限制**: 严格执行只读策略，任何非只读语句（如 `INSERT`, `UPDATE`）都将被拒绝并返回错误信息。
    *   **输出**: 返回查询结果的 JSON 字符串数组，并经过 `truncateResult` 处理。
*   **`sqlite_execute` 工具**:
    *   **功能**: 允许执行 `INSERT`, `UPDATE`, `DELETE`, `CREATE`, `ALTER`, `DROP` 等数据修改或 DDL (数据定义语言) SQL 语句。
    *   **输入**: 接收 `sql` (SQL 语句字符串) 和可选的 `params` (用于参数化查询的数组)。
    *   **限制**: 严格执行数据修改策略，任何只读语句（如 `SELECT`, `PRAGMA`）都将被拒绝并返回错误信息。
    *   **输出**: 返回一个 JSON 对象，包含 `changes` (受影响的行数) 和 `lastInsertRowid` (最后插入行的 ID)。
*   **`sqlite_list_tables` 工具**:
    *   **功能**: 列出当前 SQLite 数据库中所有表和视图的名称及类型。
    *   **输入**: 无。
    *   **输出**: 返回一个 JSON 数组，每个元素包含 `name` (表名) 和 `type` (类型，如 'table', 'view')。
*   **`sqlite_describe_table` 工具**:
    *   **功能**: 描述指定表的结构，包括列的 `cid` (列索引), `name` (列名), `type` (数据类型), `notnull` (是否非空), `dflt_value` (默认值) 和 `pk` (主键位置)。
    *   **输入**: 接收 `table` (表名字符串)。
    *   **输出**: 返回一个 JSON 数组，包含指定表的所有列定义。
*   **启动逻辑**: `runStdio()` 函数负责初始化 `StdioServerTransport` 并连接 `McpServer`，从而启动整个服务。它还会检查 `SQLITE_DB_PATH` 环境变量的设置。

## 4. 影响与风险评估
*   **破坏性变更:** 无。此变更引入了一个全新的功能模块，不会对现有系统造成破坏。
*   **测试建议:**
    *   ⚠️ **环境配置**: 验证在未设置 `SQLITE_DB_PATH` 环境变量时，服务器是否能正确启动并报错。
    *   ✅ **`sqlite_query` 功能**:
        *   测试有效的 `SELECT`、`PRAGMA` 和 `WITH` 查询，包括带参数的查询。
        *   测试尝试执行 `INSERT`、`UPDATE`、`DELETE` 等非只读语句时，是否能正确返回错误。
        *   验证结果截断功能 (`truncateResult`) 在返回大量数据时是否按预期工作。
    *   ✅ **`sqlite_execute` 功能**:
        *   测试有效的 `INSERT`、`UPDATE`、`DELETE` 和 `CREATE TABLE` 等语句，并验证 `changes` 和 `lastInsertRowid` 的返回值。
        *   测试尝试执行 `SELECT`、`PRAGMA` 等只读语句时，是否能正确返回错误。
    *   ✅ **数据库结构探索工具**:
        *   测试 `sqlite_list_tables` 在空数据库和包含多个表/视图的数据库中的行为。
        *   测试 `sqlite_describe_table` 对现有表和不存在的表的描述功能。
    *   ✅ **错误处理**: 验证所有工具在数据库操作失败（例如，SQL 语法错误、表不存在）时，是否能返回清晰的错误信息。
    *   ✅ **路径验证**: 确保 `getDb()` 和 `getReadonlyDb()` 对 `SQLITE_DB_PATH` 的路径验证（目录和文件存在性）是健壮的。
